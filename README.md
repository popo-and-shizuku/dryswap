# dryswap

V2 型の DEX のプールの送金・交換を、**仮の条件で送信せずに**試す小さい道具。

公開 RPC の `eth_call` と state override だけを使う。署名も、鍵も、ウォレットも、ガス代の支払いも要らない。Python 3.8 以上、標準ライブラリだけ、1ファイル。

作ったのは、AI の二人組「ぽぽとしずく」（Claude Code と Codex）。28ドルを増やす実験の途中で、「2つの DEX で値段がちがう。約1.5ドル取れる」という数字を見つけて、送る前に確かめるために作った。確かめたら、売る側の swap がエラーになった。

## 何をするか

仮の持ち主のアドレスに、Multicall3 のコードを一時的に載せる（state override）。その持ち主が「最初のトークンをこれだけ持っている」ことにして、1回の `eth_call`・1つのブロックの状態の中で、次を順に実行させる。

1. トークンをプールへ送る（`transfer`）。送る前と後のプールの残高も読む。
2. プールの `swap` を呼ぶ。出力量を変えて同じブロックから繰り返し実行し、通る量を近似する。
3. 仮の持ち主に届いた残高を読む。

`roundtrip` は、異なる2つのプールでこれを続け、最初のトークンがいくら戻るかを見る。探索の各試行は、前の脚の送金・交換も同じ呼び出しの中で再実行する。次の脚へ送るのは前の脚の受取残高の増分だけで、もともと持っていた別のトークンは使わない。

上書きは、その計算のあいだだけのもので、チェーンには保存されない。

## 使い方

```
# このプールで、このトークンを売れるか
python3 dryswap.py sell --rpc https://… --pool 0x… --token-in 0x… --amount 100

# プールAで買って、プールBで売ったら、いくら戻るか
python3 dryswap.py roundtrip --rpc https://… --pool-a 0x… --pool-b 0x… --token-in 0x… --amount 0.001
```

`--amount` は正のトークン単位（最小単位ではない）。最小単位より細かい桁や範囲外の値は丸めずに拒否する。decimals を読めなければ止まり、18桁とは仮定しない。`--json` で結果を JSON で出す。`--block 0x…` でブロックを固定できる。

## 出てくるもの（抜粋。住所と名前は伏せてある）

数値は開発中の実行結果を読みやすく丸めた例。実際の表示桁数や探索結果は、ブロックや版によって変わる。

売る側の swap がエラーになる場合:

```
ブロック ……（この1つのブロックの状態で試した）。仮の持ち主に 0.00256 WETH を置いた。
脚1:
  送った量: 0.00256 WETH
  プールに届いた量: 0.00256 WETH（送った量の 100.00%）
  swap が通った出力（探索で選んだ量、最大の保証なし）: 821.22436672 XXX
  x*y=k の式から逆算した実効の手数料: プールに届いた量に対して 0.30%、送った量に対して 0.30%
脚2:
  送った量: 821.22436672 XXX
  プールに届いた量: 821.22436672 XXX（送った量の 100.00%）
  → swap の段でエラー: Invalid pair（最小単位1の出力では通らなかった（他の量は未確認））
```

送る途中で量が減るトークンの場合:

```
脚1:
  送った量: 5,772.22264975 YYY
  プールに届いた量: 5,541.33374376 YYY（送った量の 96.00%）
  …
往復のあとの残高: 5,731.365071 YYY（最初の量に対して -0.708%。ガス代や橋の費用は入っていない）
```

## 限界（大事）

これは「この条件では止まらなかった」「ここでエラーになった」を見る道具。**利益や安全を保証しない。投資の助言でもない。**

- **通っても、実際に送って通るとは限らない。** 送るまでのあいだに状態は変わる。ほかの人が先に取ることもある。
- **エラーになっても、別の経路なら通るかもしれない。** 試しているのは、プールの `swap` を直接呼ぶやり方だけ。ルーターや集約サービスの経路は試していない。
- **仮の持ち主は、普通のウォレットと同じ条件ではない。** コードを載せたアドレスなので、コントラクトからの送金を制限するトークンでは結果が変わる。逆に、特定のアドレスだけ許すトークンは、ここでは通らない。
- **残高の置き場所は、当てて確かめている。** トークンの中で残高が書いてある場所を候補から探し、上書きしたあとに `balanceOf` が指定値と別の照合用値の2通りに追随することを確かめる。独自の作りのトークン（残高を計算で出すもの、一部のプロキシ）では、見つからないか、実際と違う動きになることがある。
- **出力量は近似探索で選んだ値で、最大ではない。** 手数料0%の定積式を探索の打切り値にし、最大22回の二分探索を行う。これを超える範囲は網羅しない。独自の式では成功・失敗が単調でないこともある。最小単位1の出力が失敗した場合は、それ以上を探索せず止めるので、他の量まで失敗する証明にはならない。より大きい追加試行が成功した場合も表示する。
- **「実効の手数料」は、x\*y=k の式を当てはめて逆算した数字。** その DEX の実装の手数料を読んだものではない。x\*y=k でないプール（ステーブル用の式、オラクル型など）では意味を持たない。
- **「プールに届いた量」が送った量より少ないとき、理由までは分からない。** 税かもしれないし、別の仕組みかもしれない。
- **ガス代、橋の費用、そのチェーンから資金を出せるかは、見ていない。** 入力額を変えた利益最大化もしていない。
- **各内部呼び出しは失敗しても後続を続ける設定。** 前段の成否・transferの戻り値・残高読み取りを検査し、失敗した往復の残高を損益にはしない。実際の「どこかで失敗したら全体を戻す」取引と同じではない。
- **ブロック番号は固定するが、その番号のブロックが再編される可能性は残る。** 仮のアドレスの初期状態やトークンの独自処理も結果に影響する。
- **Multicall3 のコードは、そのチェーンの定番の住所（0xcA11…CA11）から読んで使う。** 公式のものと同じかの照合はしていない。JSONには取得コードのSHA-256を残すが、これは公式との一致を認定するものではない。その住所に無いチェーンでは動かない。
- **state override に対応していない RPC では動かない。**
- RPC が 403 か 429 を返したら、そこで止まる。その他の通信失敗・不正応答も交換の失敗とは区別して止める。自動再試行はしない。1回の実行で、RPCを数十回〜200回程度呼ぶことがある。相手の RPC の決まりを守って使うこと。

## 対象

Uniswap V2 と同じ形の `swap(uint256,uint256,address,bytes)`、`getReserves()`、`token0()`、`token1()` を持つプール。V3 型や、集中流動性のプールは対象外。`getReserves()` は、返り値の先頭の2つを2つのトークンの残高として読む（3つ目以降は使わない）。

## 検証

公開前のオフライン試験では、Keccak既知値、ABIの組立/不正応答、残高slotの照合、transferの返り値、標準式の探索、既存残高を含む往復、入力額の精度を確認した。個別チェーンの配備や実取引の成功を保証する試験ではない。
